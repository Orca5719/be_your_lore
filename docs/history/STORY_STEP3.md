# Story-Level：逐事实一致性判断

现在可运行故事 → 提取重要事实建议 → 每条事实检索 → 每条事实判断 → 汇总。
这是开发检查点，还没有正式Story-Level测试集及成绩；不会写入canon。

## 体验

```powershell
Set-Location "C:\Users\Xhang\Desktop\project\worldcheck"
& ".\.venv\Scripts\python.exe" -X utf8 ".\story.py" check --text "雷感觉右胸里的亚巴顿开始躁动。" --device cuda
```

把“右胸”换成“左胸”可作对照。保留extract和retrieve；CPU可用--device cpu，auto自动选择。
--file替代--text读UTF-8文件，--json输出完整阶段记录，--top-k默认5，--index选择已有索引。
文本输出逐条展示事实、原文、必要上下文、候选证据、判断、原因和引用片段ID。

## 怎样判断

新模块story_judgement.py，当前独立提示prompts/story_consistency_v2.txt（v1保留作开发历史）。
check_story(...)复用同一个Qwen实例完成提取、重要性审查及逐事实判断；BGE/索引复用现有实现。
check_facts(retrieval, judge)接受上一小步的报告，方便单独验证判断阶段。

每次调用仅包含当前事实的主体、谓词、对象、原文、已选必要上下文和时间，以及该事实的Top-K证据正文及来源。
不提交整段故事、其他候选、检索查询或相似度分数。不按检索排名认定事实正确。
模型只输出verdict、reason和evidence_ids，事实ID由程序绑定。

- 一致：证据明确支持，或规则明确允许且条件匹配。
- 矛盾：主体、时间、条件适用时，有明确冲突；尤其区分左右、否定、数量及人物知情范围。
- 不确定：新概念、缺少证据、条件不足或资料无法厘清。没写某能力不等于没有该能力。

程序验证三个标签、非空原因及引用ID合法不重复；一致/矛盾必须引用至少一个真实候选片段。
引用返回原始正文及来源，不让模型生成来源文字。验证只保证结构和片段ID合法，不保证理由理解正确或证据充分。
空证据直接不确定，不调用模型。检索或判断失败保持error/verdict=null，不能当作正常不确定；其他条目继续。
提取及检索报告完整保留；原始判断回复、每次调用token/TTFT/decode等已有计时，以及各条wall_seconds均保存。
pipeline_seconds不含Qwen首次加载；模型加载单列model_load_seconds。实际命令体验还受启动及BGE加载影响。

## 汇总边界

存在明确矛盾则汇总矛盾，同时独立显示处理状态是否partial。
没有明确矛盾，但有不确定或阶段失败，汇总不确定；全部已检查事实一致且各阶段成功时才汇总一致。
合法空提取返回无可检查的重要事实，verdict=null，不宣称整个故事一致。
汇总仅覆盖提取出来的事实，不证明遗漏事实无矛盾；本步不检查当前故事内部矛盾。
status是程序处理状态，verdict是语义建议，两者不能混为一谈。

新增能力失败保留原始输出，没有修剪/重试后冒充成功。左胸例的理由存在过多引用及“证据6”等编号描述不准，结构合法不意味着语义解释全正确。
另用人工构造并经协议校验的“雷第一次施展控制时间的能力”隔离测试判断阶段，真实BGE和Qwen输出见reports/story_step3_uncertain_component_smoke.json；它不是LLM提取成功案例，也不是端到端成绩。
该测试没有通过：模型把“证据未提到能力”当作矛盾，且输出缺字段的JSON，程序报判断error而未接受。
尝试加入“未提及/明确否定/明确支持”三组示范后，模型又错误判一致，并引用无关的胸痛经历；保存为reports/story_step3_uncertain_component_second_attempt.json。这表明格式合法不等于证据支持，仍存在模型语义判断问题。
示范提示实验已撤回，提示和错误输出单独保存，最终仍使用首次左右心脏对照所用的story-consistency-v1。没有伪称新增能力被正确判不确定，没有无限重试或篡改失败结果。

新增八项测试覆盖证据合法性、单事实隔离、失败隔离、空证据、partial汇总、空提取及文本/JSON命令输出。全套98项回归测试通过。
冻结的38个Fact-Level文件摘要未变；旧benchmark、提示、资料、模型参数均未修改。
后续才建立正式Story-Level金标和评测，不能用这些开发对照推算准确率。

## 2026-09-17 右胸上下文与格式修复

用户输入“雷捂住右胸，感到寄宿其中的亚巴顿开始躁动。”，原v1实际输出标签矛盾，但长理由忽略了必要的右胸指代，结尾为`"evidence_ids"}`，漏冒号及数组。解析失败后旧汇总显示不确定，容易混淆处理失败和正常语义不确定。
复现原始报告：reports/story_right_context_failure.json。

当前v2提示要求先结合source_text/context_text消解“其中”等指代，理由一句话、不超过60字，禁止以故事自身或缺乏支持证明一致/矛盾。
格式/引用协议失败最多重生成一次，相同事实/证据不变；保留两个attempts及每次计时，不按重试挑喜欢的标签，合法语义回复不触发重试。
只有一种确定性规范化：JSON恰好在末尾写成`"evidence_ids"}`，补空数组后其余字段完全合法，且verdict是不确定，才能接受。记录format_normalizations及原始回复。对一致/矛盾不补证据，其他错误不修剪、不猜测。
汇总新增complete/display。处理不完整显示“检查未完成，不能给出完整结论”；已有成功矛盾时说明“检查未完成；已发现矛盾”。JSON仍保留兼容verdict，但不能把失败混为正常不确定。

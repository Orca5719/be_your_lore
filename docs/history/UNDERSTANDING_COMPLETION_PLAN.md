# 语义理解模块收尾

本轮完成整个模块；其他四阶段留到后续模块交付。旧benchmark冻结不动。

1. 引用补齐职责收敛：模型提出主体，程序寻找名称原文位置。只有当前窗唯一且位于事件之前的主体出现可自动附加为名称依据，记录操作；不改主体/事件，不把名称出现称为指代判断通过。多候选交LLM选，不成功明确待复核。消除普通句子因为模型漏填context而整项丢失。
2. 一次有限覆盖补提：对没有合法事件引用的target片段单独请求，不重写已接受事件；补提失败继续暴露缺口。分窗可承载多个上下文句，长片段无截断切分；事件稳定排序，完全重复项合并来源，同义项不自动合并。
3. JSON/schema错误一并可重试；记录每次调用与生成指标。纯程序失败不能混成无事件；空/过长/文件输出错误有明确反馈。
4. 发布模块JSON schema、API及CLI说明；输入限额、覆盖/来源检查不代表语义正确写明。
5. 先加回归测试观察失败；真实GPU测试至少12类例子，保存原始报告和助手语义审阅，不用LLM自评，不称正式Story benchmark或人工认证金标。包括日常、心理、否定/左右、条件/先后、对白、梦境、计划、隐喻、指代不清、环境、多实体、长文。
6. 检查旧freeze，全套回归通过，记录结果及残留模型错误，LOG更新，模块独立可用。

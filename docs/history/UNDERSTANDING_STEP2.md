# 语义理解第二小步：明示状态与主体依据

## 边界

explicit说明原文是否直接表达这一命题，不说明命题是否客观确定。“觉得危险”明示角色的看法，不证明实际危险；“梦见”明示梦境，不证明现实发生。“感到模糊的熟悉”是直接写出的心理状态，应explicit=true/observed。根据攥紧手指推测紧张才是explicit=false/inferred，不能改成确定紧张。新的understanding_v2提示采用这个定义，v1提示及实际报告保留供比较。

## 引用处理

模型解析代词为名字时，名字必须出现在选定source或context文字里。程序仅检查逐字主体依据，不能证明代词理解正确。指代不明可保留原文“他”，不猜名字；别名或归纳称呼没有逐字依据可能被拒绝，这一版没有自动做实体归一化。

缺少主体context时，如果主体名字在当前窗口出现，额外调用一次LLM只选择context_ids。修复协议只允许candidate_index和context_ids，程序保留其他字段不变，合并原context并再次验证引用。没有依据/多余语义字段/越窗引用都不接受。每个引用修复调用记录raw/attempt/指标；初次候选回复也保留，格式重生成与引用补充分别记录。原文没出现的主体不尝试补依据。

## 学习实验

`python -m agent_pipeline.experiments.check_understanding_v2`一次加载GPU模型，依次跑明示熟悉感、看法和计划、液化手臂三个短例子。结果写入本目录reports独立文件；属于小规模观察实验，不是正式benchmark，也不是完整性验收。

新增7项回归测试（主体上下文、虚构主体、不明指代、只引用上下文、受限引用补充、禁止语义改写、候选名称出现位置），合计134项测试通过。旧benchmark冻结内容继续只读校验。

## 真实观察结果与未解决问题

三组GPU实验报告均独立保存，没有覆盖失败。最后三例实验understanding_v2_20260918T064222Z_c62bfc.json中：熟悉感正确标为明示；看法保留belief、计划保留plan；银色手臂的两项变化保留且引用补充成功。然而前两个例子的引用补充选择了不含主体名称的当前片段，被二次验证拒绝，仍为partial。该看法例子的“不认识他”被模型标为belief，时间/心理条件还有遗漏，未宣称分类正确。

引用补充输入增加actor_mentions表（只列出名称逐字出现位置，保留所有候选，让LLM选择），并另跑熟悉感例子，报告mental_explicit_reference_hints_v2.json。模型依然选择S2/S3而非含雷姓名的S1，未通过验证。候选的内容在rejected/raw保留，没有变成合法事件。名称表不是自动指代判断，更不能保证模型遵守引用要求。本小步提高了明示心理状态边界及失败可观察性，主体上下文自动补充可靠性仍未解决，下一步不能把这些partial报告当成完整语义理解。

本小步尚未接事件筛选、retrieval、judge、report。下一步由筛选模块保留可能受世界观约束或影响世界观的事实，理解阶段原始日常事件仍保留。

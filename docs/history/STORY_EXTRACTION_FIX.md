# Story 提取：预算及输出边界修复

本步修改 story_extraction.py，不改冻结的Qwen加载/生成器、Fact-Level benchmark、检索及判断提示。

提取请求保留完整story；source_spans压缩为编号→原文文字，不再传每条start/end，也使用紧凑JSON。字符偏移及原文完整保存在本地，继续用于事实定位和逐字引用验证。真实复测发现只传编号表会漏提，因此没有采用那种更激进的压缩。

调用前用当前模型的本地tokenizer和聊天模板测量真实输入，输出预留为min(1536,4096−输入tokens)。剩余不足256则明确报错，不截断原文；若生成达到输出上限且没有结束，原有生成器仍报错。800字符依然不保证所有文字组成都在token预算内。

输出必须先包含完整有效JSON。仅允许移除两种已观察到的尾部：明确以“说明：/解释：”开头且不含JSON括号的说明文字；一个多余的双引号。记录format_normalizations并保留raw_output。多个对象、损坏JSON及其他尾部继续拒绝。恢复后必须照常验证字段、来源、主体依据和重要性，不用这些规则修正事实语义。

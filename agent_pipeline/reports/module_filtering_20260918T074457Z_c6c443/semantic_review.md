# 事件筛选模块：助手语义审阅

本轮7条观察：6条助手编写的语义事件夹具，1条来自第一模块真实CUDA输出。不是人工金标或冻结benchmark，不生成正式Accuracy/P/R/F1。dataset.json、raw.jsonl、report.json原样保留；snapshot_stable=true。3条ok、4条partial是处理状态，不是正确率。模型本地Qwen3-4B-Instruct-2507，CUDA。

| 案例 | 状态 | 观察 |
| --- | --- | --- |
| F01 普通日常 | ok | 普通喝水、坐下系鞋带、窗帘气氛均忽略；前一轮v1提示漏答的输出仍保留在此前独立报告中。 |
| F02 喝水毒发及宿主 | ok | 毒发、宿主保留，但错误忽略毒发前因喝水；原因还把倒地说成死亡、把生理事件称为认知变化。第一轮v1曾保留喝水，v2出现回退，不能宣称普遍改善。 |

## 工程验证与限制

18项新增筛选/CLI测试覆盖原事件不变、缺答/重复/未知编号、格式重试、运行失败、上游partial/error继承、指代/推断忽略保护、输入预检查、读取事件报告跳过理解及两层共享模型；全套168项回归测试通过。只读审查发现的review_reasons非法项导致TypeError、上游error降级问题已先加失败回归后修复，审查复核18项通过。

筛选请求约3.76–6.80秒，首次加载17.56秒单列；不含重新提取故事，不是完整五阶段延迟。CPU入口保留，但本轮没有CPU模型性能测试。

核心质量缺口是因果前提/验证依据遗漏、保留阈值偏保守以及原因中的推断或幻觉。keep只代表建议送往后续核对，不表示原事件真实或原因可信；ignore也可能误筛，所有原事件仍保留。当前是可运行可追溯的模块基线，不能称为语义质量全通过。
